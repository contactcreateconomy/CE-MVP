## 4. Domain Context
- **Terminology:** *Storefront* = a creator's commerce surface on their Distribution (one per verified user). *Rocketeer* = the public badge marking an **approved, active** storefront operator (a capability marker, **not** a warranty). *storefrontProduct* = a creator's **promotion of a `tool`/product** (references the canonical `tools` record where one exists — the Product-Promotion layer). *storefrontLink* = the approved, **immutable** external destination behind a product's BUY button. *Commercial package* = the locked bundle (link + name + merchant + final domain + image + description + claims + disclosure + CTA label + regions + category). *Product Discussion* = M6 comments on a product (renamed from "buyer shout-box" — "buyer" is inaccurate until purchase is verified). *Qualified CTA* = a BUY click that passes the M12 gate (the only click that mints Signal).
- **Invariants:**
  - **INV-1 No-URL preserved.** External URLs exist ONLY as an approved `storefrontLink`, reachable ONLY via the BUY redirect. Post/comment/bio bodies stay URL-free (DEC-M4-URL). A composer product-tag is a **structured entity reference** (a canonical token), never body text parsed into a link.
  - **INV-2 Lock the package at the persistence layer.** After `approved_locked`, the commercial package is **immutable in the database** (a write to any locked field when `validationState=approved_locked` **throws** — a Convex schema validator, not a UI guard). An edit is a NEW `storefrontProductVersion` → re-validation; the active product references exactly one approved version; admins **never edit a locked version in place**. **Material vs non-substantive is an explicit allowlist** (R-PACKAGE) so a substantive change can't hide inside "claims"/"disclosure."
  - **INV-3 Validate the FINAL destination, and keep validating.** Follow the full redirect chain (SSRF-safe headless) to the **final registrable domain**; store a content **fingerprint**; **re-scan** on a **partly-randomized** cadence (24h high-risk / 7d normal / on complaint / on redirect/DNS/cert change); **any fingerprint drift → auto `under_review`** (BUY disabled, storefront stays visible). A **buyer report of a destination mismatch triggers an immediate out-of-cycle re-scan** (not a wait for the next window); a **redirect-chain change triggers review even if the final domain is unchanged**. Never approve because the first network hop is unchanged.
  - **INV-4 BUY = internal id only, and context-aware.** `/go/{storefrontLinkId}` → server resolves the locked destination; **no** client-supplied `url`/override/redirect; server-generated clickId; redirect only after a **deliberate** activation (no prefetch/iframe/on-hover/popunder). **The endpoint is NOT a blind 302** — it **auto-redirects only for an in-app request** (valid session / `Referer` = createconomy.com); an **off-platform hit** (the link pasted into email/SMS) renders the **interstitial with NO auto-redirect** ("you're leaving Createconomy → [merchant]; if you didn't click this intentionally, close this page"). This stops our trusted domain being weaponized as a link-shortener/cloaker (GLM fatal).
  - **INV-5 Aggregate-only, never buyer identity, anti-differencing.** Seller analytics are aggregate by default; **never** named viewers/wishlisters/clickers, buyer email/IP/device, exact click times, session/anonymous ids, or individual journeys; a buyer's Createconomy identity is **never linked to their off-platform purchase**. **Min-cohort alone is insufficient** — the read path enforces a **fixed privacy-query contract** (R-ANALYTICS): fixed time buckets, a min reporting delay, k-anonymity (min distinct users/cell), **parent/child suppression** (subtraction can't reveal a hidden cell), no arbitrary multi-dimensional filtering, rounded low counts, exports obey the same rules, overlapping queries rate-limited. User-level contact needs a separate explicit user action + consent.
  - **INV-6 We never touch money.** Commission flows merchant → creator's own affiliate account, outside us. We ingest conversion **notifications** (later), never payments (no 1099 / payment-settlement-entity exposure).
  - **INV-7 Signal only from a qualified CTA (M12).** Product-view = 0, **wishlist = 0**, raw click = 0; a qualified CTA mints a small provisional Signal; a **network-verified** conversion mints the higher one; refund = reversal. Self-reported sales **never** award full Signal. Seller Signal never derives from marketing repeatedly to the same actor.
  - **INV-8 Review firewall = conflict graph.** A rating/review of a product the reviewer sells (or is conflicted on) is **flagged + excluded** from the community aggregate but stays **readable + labeled** ("Seller-affiliated — not in Community Score"; label not hideable; false claims still moderated); never silently deleted unless deceptive. States `declared / suspected / confirmed / cleared`; a **same-device/phone-cluster signal alone cannot reach `confirmed`** (households/offices/agencies are legitimate overlap) — `confirmed` needs human review + corroboration.
  - **INV-9 Rocketeer = capability, not warranty.** Badge states provisional/active/paused/revoked; minted **active only at storefront ACTIVATION (≥1 approved product)**; revocable; a tooltip states it is not a product guarantee. **Revocation never infers buyers** (we can't know who purchased — INV-5): it notifies **followers + explicit storefront/product watchers + safety-notification opt-ins** + posts a **public storefront notice**; a confirmed buyer is notified ONLY where a merchant/network returned an authorized, consented, user-linked transaction (GPT fatal).
  - **INV-10 Personas + staff excluded** from every metric, Signal, and Product Discussion count (carry).
  - **INV-11 Allowlist only.** Phase-1 categories = the allowlist; distinct rejection reasons **"unsafe"** and **"off-topic"** (protects the niche + SEO).
  - **INV-12 Manual-first.** The auto-screener assists; a human decides at launch. The **~1,000 store-requests** validation gate proves demand before automation.
- **Actors:** requester (eligible member), Rocketeer (approved operator), buyer/visitor (browses, clicks, wishlists, discusses), operator (validates, moderates, curates seed stores), merchant (complaint portal), automated (re-scan/drift/auto-screener/settle/rollup/reconcile crons).
- **Source of truth:** `storefrontLinks` = the authoritative locked destination; `storefrontProductVersions` = package history; `rawEvents`/`storefrontClicks` = click/intent events; `salesEvidence` = conversion proof; everything else = rebuildable projection.

## 5. Request → Rocketeer
- **R-REQUEST (eligibility → application → approval → activation):** eligibility = **profile complete** (all directly-fillable fields, prefer-not-to-say counts — DEC-M7-COMPLETION; **not** a naive 100% bar) + **≥1 social handle attached** + **eligible trust tier** + no active integrity/moderation hold. A **Store-Readiness checklist** shows what's missing; the request button is disabled until green. Application (tap-first): intended categories, affiliate networks/programs, expected product count, promotion experience, **attestations** (I own/authorized to use these links · the program permits promotion from a Createconomy storefront · region-eligible · will disclose material changes), and acceptance of the **Store Terms** + the **data-use page** (R-DATA-HONESTY). Operator approves/rejects/requests-info (reason codes). On approval → `storefront.status = setup`; the **Rocketeer badge is provisional** (internal). The badge goes **active + public + the store goes public only at ACTIVATION** (≥1 approved product). **One storefront per verified user** (device/identity checked). No fake approval SLA shown; a real SLA is set operationally.

## 6. Link & package validation (the security core)
- **R-VALIDATE (submit → auto-screen → human → lock):** on `product.submit`, an **isolated outbound inspection service** (not a privileged Convex action) runs `link.validate`: HTTPS-only; normalize host; reject creds/IP-literal/loopback/private/reserved/multicast/link-local; **resolve + re-resolve DNS before connect** (anti-rebind); follow ≤5 redirects revalidating each hop; render with a **headless browser** (executes JS — catches JS redirects/cloaking); cap size/timeout; no cookies/auth; egress network-blocks internal ranges independently (extends DEC-M2-SSRF). It produces a **destination FINGERPRINT** (final registrable domain + redirect-chain hash + title hash + content perceptual/text hash + extracted product + category + Safe Browsing/PhishTank/OpenPhish class + scan location + device profile + ts), checks the **Phase-1 category allowlist**, screens **metadata** (plain-text; no HTML/scripts/user-SVG; image re-encode; fixed CTA vocabulary; brand-impersonation; no fake urgency / system-notification styling / unproven "official"), and sets `disposition` (pass / needs_human / fail). **A human always decides at launch**; on approve → the whole **commercial package is locked** (`approved_locked`, immutable per INV-2). Reasons come from an enumerated dropdown (incl. the two `unsafe`/`off_topic`).
- **R-DRIFT (re-scan):** `link.rescan` cron re-runs the scan on a **partly-randomized** cadence (24h high-risk / 7d normal / on complaint / on redirect-DNS-cert change — timing not fully predictable); compares the current fingerprint to the stored one; **any material change (final domain / category / safety class / content) → `under_review`** (BUY disabled, storefront visible, operator notified). **A buyer report of a destination mismatch → an immediate out-of-cycle re-scan** (not a wait for the schedule); a credible complaint can **pause** the link before the investigation completes. A **redirect-chain change triggers review even when the final domain is unchanged** (a materially different intermediate). For high-risk, scan multiple **regions + device profiles** (anti geo/device cloaking). No periodic scanner can fully eliminate a between-scan swap — the Product Discussion (buyers as canaries) + fast takedown are the human backstop, and **approval is never a warranty**.
- **R-PACKAGE (versions + the materiality allowlist):** every approved package = an immutable `storefrontProductVersions` snapshot; an edit request creates a new version in `under_review` while the current version stays live (or the product is paused); approval swaps the live version. **Material (→ new version + revalidate):** submitted URL, redirect chain, final registrable domain, merchant/offer identity, name, category, commercial claims, price/discount claim, image/logo, CTA wording, disclosure class, affiliate program, geo availability, intended audience, buyer-visible description, SubID/tracking behavior. **Non-substantive (no revalidation):** storefront ordering, collection assignment, internal/seller-private notes, visibility pause, whitespace with no rendered-text change, accessibility metadata that alters no claim, internal analytics/status flags. Admins **never edit a locked version in place.**

## 7. Storefront + composer + post block
- **R-STOREFRONT:** a store tab on the Distribution profile; header (Rocketeer status + Distribution metrics + **store disclosure banner** + search + collections); simple product cards (image · name · category · one-line use-case · **community review score from `tools`** · **affiliate disclosure chip on the card face** · "View offer" · merchant-domain preview; **no exact price unless verified + dated**, else "Check current pricing"); **collections** (seller/operator-defined groups; no themes). "Unlimited" products = no permanent ceiling, not unlimited simultaneous review (R-OPERATOR caps). Store pause available (whole store / product / tag — immediate, no review).
- **R-COMPOSER:** a Rocketeer gets an **Add Products** control → search **own active/approved products only** → tag ≤**5**; a tag inserts a **structured product token** (canonical reference), not parsed body text; a live **"3 of 5"** counter; a **commercial-density guard** (≤50% of the seller's published posts over a rolling 30 days may be product-tagged; recommended 1-2/post); **no raw URL input, ever**. If a tagged product becomes unavailable before submit → prevent publish + identify it.
- **R-BLOCK (post product block):** a separate block, **subordinate to the post** (max ~2 expanded + "view N more"), single disclosure above it, each product a card with the **live** product reference (INV-2/INV-3). Product pulled/under-review → the card **degrades gracefully** ("currently unavailable"), BUY disabled, but the **historical commercial context is never erased**. No fake discount/scarcity badges, no autoplay motion.
- **R-CARD (hover / tap):** shows image + name + merchant + **"sold by [handle]" + disclosure (same size/prominence as price)** + community score + **View offer / Visit merchant** (primary) + **Wishlist** (secondary, lighter — it's our signal, not the seller's goal). Desktop hover = **preview only** (no tiny accidentally-clickable purchase button); mobile = **bottom-sheet**, external action = a **deliberate second tap**; the disclosure/trust line **survives the mobile collapse**.

## 8. BUY, clicks, and Signal
- **R-BUY (context-aware redirect — NOT a blind 302):** `/go/{storefrontLinkId}` (internal id only, INV-4) → verify `storefrontLinks.validationState = approved_locked` → resolve the locked destination. **In-app** (valid session / `Referer` = createconomy.com): a fast **interstitial** ("You're leaving Createconomy → [merchant]"; merchant domain from the stored fingerprint, **not** fetched on the hot path) → server clickId + append the network's **SubID** if registered (R-SALES) → 302 to the stored URL. **Off-platform** (missing internal Referer — pasted into email/SMS): render the interstitial with **NO auto-redirect** ("if you didn't click this intentionally, close this page") — stops our domain being abused as a trusted link-shortener/cloaker (GLM fatal). Never a client `url` param; never client-rebuilt affiliate params; the **hot path never executes remote JS or refetches** the destination; redirect only on real activation (not prefetch/bot/social-preview).
- **R-CLICK-SIGNAL (qualified CTA → M12):** each BUY writes an append-only `storefrontClicks` row + a `rawEvents` outcome; `click.settle` applies the **M12 qualified-CTA gate** (eligible human · not seller/associated · once per actor·product·contribution·window · product visible · min engagement · deliberate · redirect done · no velocity/datacenter/device-cluster/reciprocal-clicking · settlement) → provisional Signal (weight 10). GLM add: a **CTA-to-engagement ratio** ceiling (CTA ≫ organic engagement → the Signal value is choked). A **network-verified conversion** (R-SALES) mints the conversion Signal (25); refund → reversal. **Wishlist = ZERO Signal.** One outcome may be fractionally attributed across an eligible journey, but **total awarded credit never exceeds the outcome's versioned Signal value** (no >100%). Everything is legitimacy-weighted and personas/staff excluded.

## 9. Discussion, firewall, analytics, sales
- **R-DISCUSSION (Product Discussion — reuses M6):** M6 comments attached to a product via a product `threadContext`; **default-sorted by the M6 legitimacy-weighted ranking** (a low-legitimacy simultaneous pile can't dominate — anti-brigading); velocity auto-collapse; per-user rate limit; duplicate-complaint clustering; **the store owner CANNOT delete, only HIDE-for-moderator-review** (preserves buyer warnings); seller responses badged; conflict-of-interest labels; a **verified-buyer** tag only where a click-then-return behavioral signal exists; personas excluded.
- **R-FIREWALL (conflict graph):** `reviewConflicts` flags a `toolRating`/review (states `declared / suspected / confirmed / cleared`) when the reviewer is the seller / co-owner / operator / declared team / link-owner / same-device-or-phone cluster (via M12 `engagementEdges`/legitimacy) / reciprocal-commercial / compensated. Detection routes to **human review** (`conflict.detect` cron; not auto-block); a **same-device/phone signal alone cannot reach `confirmed`** (households/offices/agencies are legitimate) — `confirmed` needs corroboration. A `confirmed` conflicted review is **excluded from the `tools` aggregate** + earns **no Signal** + gets **no preferential placement**, but stays **readable + labeled** (the label is not hideable; false claims still moderated); never silently deleted unless deceptive (extends DEC-M5-AGG).
- **R-ANALYTICS (aggregate-only + a fixed privacy-query contract):** `storefrontAnalytics` rollups per storefront/product in three honest buckets — **Traffic** (store/product views, unique qualified viewers, source post vs storefront), **Intent** (qualified clicks, CTR, wishlist adds, repeat visits), **Confirmed** (network-verified conversions + value **only where authorized**). **Min-cohort alone is insufficient against differencing/timing re-identification** (GPT/GLM/Sonnet), so the read path enforces: **fixed time buckets** (smallest = 1 day; no arbitrary timestamp ranges), a **≥24h reporting delay**, **k-anonymity** (min **5** distinct users per returned cell; a source/post below k is bucketed to "Other" or suppressed), **parent/child suppression** (subtraction can't reveal a hidden cell), **no arbitrary multi-dimensional filtering** (capped dimensions/query), **rounded** low counts, **no real-time per-user**, exports obey the same suppression, **wishlist gets stronger suppression** (intent is private), and overlapping queries are **rate-limited + audited**. Internal ids / exact click times / session / anonymous ids **never** enter seller analytics. A data-quality label on every figure. **Cold-start context** in the empty state so "340 clicks, 0 sales" doesn't read as failure. It answers "which content/products perform?", never "which person considered buying?"
- **R-SALES (confirmation intake — launch scope):** (1) **SubID passthrough** via a per-network **`subIdRegistry`** (param name / value format / length / returned-in-report / permitted / CC-generates / breaks-signature — **never append unknown params**); our **CC-generated opaque** clickId flows in the SubID (**validated/sanitized; never carries buyer PII into Createconomy analytics** — SubIDs are seller/campaign-set, not buyer-supplied); the seller reconciles in their own dashboard (Impact/ShareASale/Awin/CJ; **not** Amazon). (2) **Unique coupon codes** (direct-merchant; confirmed only after merchant report). (3) **Self-report** (`salesEvidence` flagged `unverified`; operator/redacted-txn/SubID-amount-time match; random audit) — **never full Signal**, anomaly-checked. **Fast-follow:** signed **S2S postback** (HMAC, idempotent conversion id, refund/reversal) for 1-2 direct-merchant pilots. **Deferred:** universal network API, extension, Amazon conversion API (+ legal review), cross-network identity, payout reconciliation. **Rule:** never label a click as a sale; "who sold" is ours only with merchant/network proof.
- **R-DATA-HONESTY:** a plain-language **`/how-we-use-your-store-data`** page (pattern of `/how-we-use-ai`), linked at the request step and accepted before approval: individual performance stays **private to the seller**; only **aggregate/anonymized** trend data informs the platform or may be sold; the seller can review exactly what "aggregate" means. The pitch copy: *"Keep 100% of your commission. We provide the storefront, discovery, and analytics, and use aggregated activity to improve discovery and integrity — subject to privacy controls."*

## 10. Operator & cold-start (+ FE reference)
- **R-OPERATOR:** the validation queue shows **auto-screen results before the decision** (SSRF/Safe-Browsing/final-destination/fingerprint/category/metadata warnings) + applicant panel (standing/tier/moderation history/social/prior links/associated accounts/existing stores). Actions: approve / reject (reason dropdown + template copy) / request-info / escalate / block-domain / pause — each with a reason code + `auditLog`. **Throughput controls:** per-Rocketeer caps (new ≤5 pending / ≤20 approved; grow with clean history), **batch validation** (≤10/session), an **auto-screener** pre-flight from day one (state `auto_screened`). **Circuit breakers:** a store-level auto-suspend on N complaints / M hours; a 3-strike → revoke + close; emergency single-product pull (instant). Merchant complaint portal → `merchantComplaints` → takedown flow. Revoking Rocketeer reuses M12 "accuracy-not-punishment" framing and notifies **followers + explicit storefront/product watchers + safety opt-ins + a public storefront notice** — **never inferred buyers** (INV-5/INV-9); a confirmed buyer only where a merchant/network returned a consented, authorized, user-linked transaction.
- **R-COLDSTART:** launch with **10-20 operator-curated "platform-curated" seed stores** (clearly labeled, not user-owned) to demonstrate the surface and drive toward the ~1,000-request gate (no stores → no behavior → no requests).
- **§10 Customer FE (DEFERRED — reference for the FE phase):** the request flow (application not form; eligibility before the button), the storefront, the composer product-tag, the post product block, the hover/tap card, the analytics view, and mobile (bottom-sheets, disclosure survives collapse, BUY primary / wishlist secondary) are specified in `Aggregated/m10-affiliate-store.md` §E and built in the FE phase.

## 11. Data Model (Bible "Affiliate storefront (M11)" — summary)

- `storefrontProductVersions` *(immutable package history)* — storefrontProductId, versionNo, packageHash, name, merchant, image, description, claims, disclosureClass, ctaLabel, regions[], category, storefrontLinkId, approvedByUserId, approvedAt.
- `storefrontLinks` *(approved immutable destination — NEVER exposes the affiliate id)* — submittedUrl, finalRegistrableDomain, redirectChainHash, network, programName, **affiliateAccountRefMasked**, permittedChannels, geoEligibility, selfReferralPolicy, subAffiliatePolicy, **validationState {pending|approved_locked|under_review|rejected}**, fingerprintId, lockedAt.
- `linkValidations` *(audit)* — storefrontLinkId, runType {initial|rescan}, disposition, fingerprint{finalHost,redirectHash,titleHash,contentHash,product,category,safety,scanRegion,deviceProfile,ts}, safeBrowsing, phishtank, reviewerUserId?, createdAt.

## 16. Edge Cases & Failure Recovery
- **Approve-then-swap** → package immutable at the persistence layer (INV-2; materiality allowlist R-PACKAGE). · **Destination drift/cloaking** → randomized re-scan + fingerprint diff → auto `under_review` (INV-3); multi-region/device high-risk; a **buyer report → immediate out-of-cycle re-scan**. · **`/go` link pasted into email/SMS (trusted-domain phishing / link-shortener abuse)** → **context-aware endpoint**: off-platform hits get the interstitial, **no auto-redirect** (INV-4/R-BUY). · **JS-redirect masking** → headless render, not `fetch`. · **Analytics differencing / timing re-identification** → the fixed privacy-query contract (fixed buckets, ≥24h delay, k≥5, parent/child suppression, no arbitrary filtering — R-ANALYTICS). · **Self/associated click fraud / click-farm** → M12 gate + CTA-to-engagement-ratio ceiling → excluded; wishlist=0. · **Review via alt** → conflict graph → human review + labeled exclusion (same-device alone ≠ confirmed; INV-8). · **Brigaded Discussion** → legitimacy-weighted sort + velocity-collapse + owner-can-only-hide. · **Rogue Rocketeer** → strikes + circuit breaker + emergency pull + revoke **notifies followers/watchers + public notice (never inferred buyers)**. · **Off-topic-but-safe product** → `off_topic` rejection (INV-11). · **Not entitled to the link** → attestation + `ownership_unverified` reject; never expose the affiliate id. · **Amazon redirect ToS** → **legal review** + a native-Amazon path before Amazon enables (DEC-M11-AMAZON). · **Validation service down** → fail-closed (`needs_human`). · **Cold start** → seed stores.

## 18. Fixtures, Tests & Acceptance Criteria
- **Fixtures:** an eligible requester; a Rocketeer with 5 approved products; a link that passes then drifts to phishing; a cloaking destination (clean to scanner, malicious to buyers); a self-clicking seller + a click-farm; an alt-account reviewer; a brigaded product; an Amazon link; a store hitting the complaint circuit breaker.
- **AC (Given-When-Then):**
  - **AC-1** Given an approved+locked product, When any code writes to a locked package field, Then it throws (package immutable) and an edit creates a new version in `under_review`.
  - **AC-2** Given an approved link whose destination later changes registrable domain, When `link.rescan` runs, Then the product auto-sets `under_review`, BUY is disabled, the storefront stays visible, and the operator is notified.
  - **AC-3** Given a BUY endpoint call, When a client supplies a `url` param, Then it is ignored; only `/go/{storefrontLinkId}` resolves the locked stored destination.
  - **AC-4** Given a seller self-clicks their own product (or a click farm), When `click.settle` runs, Then those clicks are `excluded` and mint **zero** Signal; wishlist adds mint zero Signal.
  - **AC-5** Given a seller reviews a product they sell (directly or via a same-device alt), When the aggregate computes, Then the review is **excluded + labeled**, not deleted, and the tool's community score is unaffected.
  - **AC-6** Given the seller analytics view, When rendered, Then no named individuals appear and any source breakdown below the min-cohort is suppressed.
  - **AC-7** Given a store request, When the user's profile is incomplete or no social handle is attached, Then the request button is disabled with a clear checklist.
  - **AC-8** Given a Rocketeer is revoked, When the action commits, Then their tagged products degrade to "unavailable," affected buyers/followers are notified, and the badge moves to `revoked` (kept in audit, off the public shelf).
  - **AC-9** Given an off-topic-but-safe product, When validated, Then it is rejected with reason `off_topic` (distinct from `unsafe`).
  - **AC-10** *(GLM — domain-hijack)* Given a `/go/{id}` request with no in-app session/Referer (link pasted into email), When the endpoint runs, Then it renders the interstitial and does **NOT** auto-redirect.
  - **AC-11** *(GPT — differencing)* Given a seller runs overlapping analytics queries that would isolate a sub-5 cohort by subtraction, When the read path serves them, Then the cell is suppressed/bucketed and exact times / session ids are never returned.
  - **AC-12** *(GPT — revocation)* Given a Rocketeer is revoked, When notifications fire, Then only followers/watchers/opt-ins + a public storefront notice are notified and **no buyer identity is inferred** from click history.
