## Shared-file serialization rule (added 2026-09-04 — FINAL-HOLISTIC-AUDIT HOL-P2-004)

Logical parallelism ≠ merge safety. P1-01a/b, P1-02…P1-08 all append regions to
`convex/schema.ts`; later phases converge on `convex/crons.ts`, `convex/lib/authz.ts`,
and the shared registries (`adminWidgets`, `eventCatalog`, `configKeyRegistry`, `auditLog`).

**Rule:** slices may be *developed* in parallel, but edits to these shared files are
**serialized through one integration pass per phase** (single merge owner, one
generated-type refresh after the batch lands, not per-slice). A parallel agent that
cannot take the integration slot works on non-shared files only. Per-slice
"parallelizable" notes below refer to semantic independence, not file-level concurrency.
