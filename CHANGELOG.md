### CODE-REVIEW PASS-1 — full-repo review: 10 CONFIRMED critical defects fixed (2026-09-13)

*11 finder angles (3 correctness + 3 cleanup + 1 altitude + 4 area sweeps covering every module) with one-verdict adversarial verification per candidate — every shortlisted finding CONFIRMED. The 10 top defects, fixed here:*

- **CI was red / prerender hard-fail:** `CmpOverlay` + `NewsletterOverlay` (layout-mounted on every `(app)` route) ran Convex hooks before the `isConvexConfigured()` early-return, and `ConvexProvider` rendered children bare without `NEXT_PUBLIC_CONVEX_URL` — convex 1.34 throws 'Could not find Convex client' even with args `"skip"`, so `next build` failed prerendering every page (CI run 34710154555: 'Error occurred prerendering page /content/spark'). The provider now always supplies a client (placeholder offline); both overlays guard-split before hooks. No-env build verified green.
- **Every feed entry-point link was dead:** feed cards, hero band, featured, What's-Vibing, and search all linked `/discussions/<raw post id>`, but the only resolver (`posts.detail.getDetail`) matched `postSeoMeta` by slug (`${baseSlug}-${id.slice(-6)}`) → 'Discussion not found' for every primary thread entry. Resolver now falls back to treating the param as a raw posts id (invalid-id strings tolerated) — one repair point, every producer fixed.
- **/search 500'd for every user:** `searchQuery` constrained the second field of `by_type_lifecycleStatus` without constraining the prefix — Convex index ranges throw at runtime (the `(q:any)` cast hid it from typecheck; source-string tests stayed green). Now walks active postTypeConfig types constraining type+status in prefix order.
- **BUY clicks never recorded (money path dead):** `recordClick` parsed productId from an always-empty location hash and promoterUserId from an absent `?p=` — both REQUIRED v.id args, so args validation rejected every click; server also trusted the client-supplied promoter id for attribution/self-click exclusion. Producers append `#<productId>`; attribution derived server-side (product → current version's link must match → storefront owner), fail-closed on mismatch; the documented-but-missing `isInApp` referrer heuristic implemented (anti-hijack branch was unreachable).
- **CAP-244 bypass via edit:** `updatePost` re-ran R-URL but none of the R-COMPOSER gates — `[[product:<id>]]` tokens injected by edit bypassed ownership, ≤5, active-storefront, and ≤50% 30d density that `createPost` enforced; the density window also counted drafts/held. Shared `assertProductTagGates()` runs on create + edit; density counts `lifecycleStatus==='published'` only (draft-padding evasion closed).
- **Qualify pipeline deadlocked:** `neighborSimilarities` didn't exclude the candidate's own embedding (forge inserts it BEFORE qualify runs) → self-cosine ~1.0 deterministically failed H-SIM-semantic (0.28) + H-DUP (0.85) for every editorial candidate → CAP-043 approval could never pass. Candidate embedding id passed in and excluded.
- **Held-rating edits skewed tool aggregates permanently:** `toolRatings.update()` masked only the PRIOR side of the aggregate delta — a held (auto-flagged) rating's edit still applied the +new side to ratingSum/ratingCount/dimensions (contradicting its own comment), and `withdraw()` masked the held prior so the phantom was never removed. Next side masked by the same eligibility — held edits are delta-neutral, only a moderator recompute as before.
- **CAP-239 requestEdit patched the LIVE product:** description/claims overwritten instantly + status flipped `under_review` → the product vanished from the `by_storefront_status='approved'` listing and BUY died while the detail page still rendered live; the immutable locked package destroyed with no version to re-validate — the `storefrontProductVersions` table existed for exactly this and was never written. Now inserts a pending version row (same locked link, proposed copy); product row + currentVersionId untouched; approved-status precondition enforced server-side. Also: activate/pause cannot reverse admin `suspended`/`closed`; `pauseMyStore` gains the capability guard + audit its siblings have.
- **Clean-file paywall bypass:** `resources/view.getViewUrl` — the mutation minting the signed clean-bucket URL — checked only auth + currentVersionId, skipping both gates its sibling `getViewerState` enforces (status `published` + acquisition): any authenticated member could fetch any slug incl. unpublished, bypassing acquire + quotas with no ledger/Journal record. Both gates now throw before the mint. Companion: the 20/week quota was structurally unreachable (ledger keyed `(user, day)`; lazy reset dead code) — single-row `by_user` lookup makes it enforceable.
- **`waitlist.markConverted` was unauthenticated:** any client could flip any emailNormalized to `converted` and stamp an arbitrary convertedUserId during waitlist admission mode (zero callers, no rate limit). Now administrator-only via `assertAdminPermission`; `contribute.eraseAttribution` now uploader-or-admin.
